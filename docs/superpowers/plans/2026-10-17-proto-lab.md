# proto-lab — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir o `proto-lab`: uma skill open source (padrão agentskills.io) que gera, a cada sessão, protótipos HTML estáticos e navegáveis com opções **estruturalmente divergentes** por ponto de decisão, dirigidas por um **seed reproduzível**, com **research citado** de concorrentes e um **juiz pré-humano** (fidelidade, estranhamento, slop, diversidade), terminando em **handoff** para implementação.

**Architecture:** O `SKILL.md` orquestra o pipeline (brief → roll → pontos → research → geração paralela por subagents → juiz em loop → apresentação → handoff). Toda a "inteligência de conteúdo" vive em `references/` (catálogo de 22 direções, fingerprints de slop, rubricas, protocolos), consumida sob demanda (progressive disclosure). O motor determinístico é Python stdlib (`roll.py`, espelho Node `roll.mjs`) + scan mecânico (`check_slop.py`), com templates HTML estáticos zero-dep (`assets/`).

**Tech Stack:** Markdown (SKILL.md + references), Python 3.8+ **stdlib only** (scripts e testes via `unittest`), Node ≥18 **built-ins only** (`roll.mjs` + teste de paridade via `node --test`), HTML/CSS estático (JS inline ≤ 30 linhas apenas na galeria/canvas).

**Spec:** `docs/superpowers/specs/2026-10-17-proto-lab-design.md` (ler antes; o plano argumenta a partir dela). Anexos: `docs/research/landscape.md`, `docs/research/directions-draft.md`.

## Global Constraints

Valores exatos; **toda task herda esta seção**:

- Scripts Python: stdlib only, sem pip; Python ≥ 3.8. Scripts Node: built-ins only (`crypto`, `fs`, `path`), Node ≥ 18.
- HTML estático: sem build, sem bundler; abre via `file://`; JS inline ≤ 30 linhas (galeria/canvas apenas); **zero scripting cross-frame** (galeria display-only).
- Sem imagens binárias; "imagens" são placeholders CSS/SVG.
- Fontes: ≤ 2 famílias + ≤ 1 mono; CDN permitido; **fallback stack da mesma classe obrigatório** em toda direção.
- Caps do pipeline: ≤ 4 pontos/sessão; 3 variantes (2 permitido via flag); ≤ 3 telas/variante; ≤ 6 fontes de research; ≤ 2 rodadas de juiz.
- Slop: **≥ 4 hits** no `check_slop.py` = reprova.
- Determinismo: mesmo seed → **mesma carta** (`direction.json` sem timestamp; é a fonte da verdade).
- Catálogo: exatamente 22 direções (D01–D22), sistema fechado.
- Docs do repo em **inglês** (SKILL.md, references, README); commits em conventional commits (`docs:`, `feat:`, `test:`, `chore:`); licença **MIT**.
- A skill não lê código/UI do projeto alvo para design (só specs/docs para requisitos).

## Review Focus

Cinco modos de falha que os testes de task fixam (mais prováveis primeiro):

1. **Seed deixa de ser determinístico** (entre `roll.py`, `roll.mjs` e re-execuções) → fixado em T10/T11 (mesmo seed = carta idêntica; paridade py↔node).
2. **Galeria/canvas não funciona via `file://`** (iframe bloqueado, JS cross-frame, caminho absoluto) → fixado em T12 (contrato dos templates) e T19 (aceitação com `file://` real).
3. **Offline mata o register da direção** (webfont não carrega e não há fallback da classe) → fixado em T07 (fallback obrigatório no catálogo) e T20 (run offline).
4. **`check_slop.py` erra na fronteira** (3 hits passa / 4 reprova; falso-positivo em fixture negativa) → fixado em T09 (fixtures de fronteira).
5. **Juiz pulável sob pressão de tempo** → fixado em T02 (linha de base verbatim), T16 (red flags no SKILL.md) e T17 (cenário de pressão com a skill).
